A Site key only collects device tokens on the web addresses (origins) allowed for your account. A page on any other origin gets `origin_not_allowed`, and its checks run without device evidence. Use this endpoint to add your origins. Call it from your server with a Secret key.

```http
POST {{RISK_API_BASE_URL}}/v1/device/keys
Authorization: Bearer sk_...
Content-Type: application/json
```

<RequestExample>
```bash cURL
curl -X POST '{{RISK_API_BASE_URL}}/v1/device/keys' \
  -H 'Authorization: Bearer sk_...' \
  -H 'Content-Type: application/json' \
  -d '{
    "publishable_key": "YOUR_SITE_KEY",
    "label": "Production web",
    "origins": ["https://app.example.com", "https://staging.example.com"]
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "project_id": "...",
  "label": "Production web",
  "origins": ["https://app.example.com", "https://staging.example.com"]
}
```
</ResponseExample>

## Request body

<ParamField body="publishable_key" type="string" required>
  Your Site key, at least 16 characters. If this value isn't a Site key on your account yet, the call registers it as one.
</ParamField>

<ParamField body="label" type="string">
  A name for the Site key, such as `Production web`. Each call replaces the current name; when you leave it out, the name becomes `Device publishable key`.
</ParamField>

<ParamField body="origins" type="array of strings" required>
  The origins to allow, at least one. Write each one exactly as the browser sends it in the `Origin` header: scheme, host and port when it isn't the default, with no path and no trailing slash. For example `https://app.example.com` or `http://localhost:3000`.
</ParamField>

## How origins work

- Origins belong to your account, so every Site key on your account works on all of them.
- Each call adds origins. Origins already allowed stay allowed, and sending one twice is harmless.
- This endpoint never removes an origin.
- Matching is exact. `https://example.com` and `https://www.example.com` are two origins, and so are your staging and production addresses.

## Response

<ResponseField name="label" type="string">
  The Site key's name.
</ResponseField>

<ResponseField name="origins" type="array">
  The origins you sent.
</ResponseField>

## Errors

| Status | `reason` | Meaning |
|---|---|---|
| 400 | `malformed_json` | The body isn't a JSON object. |
| 400 | `invalid_request` | `publishable_key` or `origins` is missing, or the Site key is shorter than 16 characters. |
| 401 | `unauthorized` | Missing or invalid Secret key. A Management key doesn't work here. |
