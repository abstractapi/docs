Read the [policies](/api/risk-platform/policies) that score your checks and change their rules without the dashboard, for example from a script or an agent. Every endpoint on this page requires a [Management key](/api/risk-platform/keys#management-key), including reads. A Secret key gets `403` with reason `management_key_required`.

| Method | Path | What it does |
|---|---|---|
| `GET` | `/v1/policies` | List all policies with their rules and current version |
| `GET` | `/v1/policies/{policy_id}` | Retrieve one policy |
| `GET` | `/v1/policies/{policy_id}/versions` | List versions, newest first, with who made each change |
| `POST` | `/v1/policies/{policy_id}/rules` | Add one rule at the end of the policy |
| `PUT` | `/v1/policies/{policy_id}/rules/{rule_id}` | Replace one rule |
| `DELETE` | `/v1/policies/{policy_id}/rules/{rule_id}` | Delete one rule |
| `POST` | `/v1/policies/{policy_id}/rollback` | Restore an earlier version's rules as a new version |
| `GET` | `/v1/registry` | List the fields a rule can test, with their operators and allowed values |

All paths are relative to `{{RISK_API_BASE_URL}}`.

Creating, renaming or archiving a policy is done in the dashboard. The API changes rules one at a time; there is no endpoint that replaces a whole policy.

## How writes work

- **Send `expected_version`.** Every write names the policy `version` your change is based on. If the policy changed since you read it, the write is refused with `409` and reason `version_conflict`, and the response includes `current_version`. Read the policy again and reapply your change.
- **The whole policy is validated.** The rule set that would result from your change is checked against the registry fields and your [Lists](/api/risk-platform/lists). An invalid rule is refused with `400` and reason `invalid_rule`, with an `issues` array naming each problem. Nothing is saved.
- **One write, one version.** A successful write adds exactly one new policy version. Sending a rule identical to the stored one changes nothing and adds no version.
- **Rule IDs are assigned by the server and never reused.** A new rule gets the next ID never used in the policy (`R6` after `R5` was deleted), because past checks name rules by ID.
- **Changes are live immediately.** The next check after a successful write uses the new rules.
- **Changes are attributed.** Each version records the Management key owner's email and the key's name, and appears in **Policy history** in the dashboard.

## The policy object

```json
{
  "id": "signup_protection",
  "name": "Signup policy",
  "version": 8,
  "protected": true,
  "archived_at": null,
  "updated_at": "2026-11-04T09:30:00Z",
  "rules": [
    {
      "id": "R2",
      "label": "Blocked countries",
      "action": "block",
      "match": "any",
      "on_unknown": "review",
      "groups": [
        { "match": "all", "conditions": [
          { "field": "ip.country_code", "op": "in", "value": "RU,IR,KP" }
        ]}
      ]
    }
  ]
}
```

<ResponseField name="id" type="string">
  The policy ID. The `signup` flow runs `signup_protection` and the `login` flow runs `login_protection`.
</ResponseField>

<ResponseField name="name" type="string">
  Display name.
</ResponseField>

<ResponseField name="version" type="integer">
  The current version. Send it as `expected_version` when you change the policy.
</ResponseField>

<ResponseField name="protected" type="boolean">
  `true` for a built-in policy.
</ResponseField>

<ResponseField name="archived_at" type="string | null">
  When the policy was archived. An archived policy can't be changed until it is restored in the dashboard.
</ResponseField>

<ResponseField name="updated_at" type="string | null">
  When the policy last changed.
</ResponseField>

<ResponseField name="rules" type="array">
  The rules, in order. See [The rule object](#the-rule-object).
</ResponseField>

## The rule object

<ParamField body="id" type="string">
  The rule ID, such as `R3`. Assigned by the server. On a replace, omit it or send the same ID; it can't change.
</ParamField>

<ParamField body="label" type="string">
  A display name. Checks return it next to the rule ID in `policy.reasons`.
</ParamField>

<ParamField body="action" type="string" required>
  `allow`, `review` or `block`. `add_to_score` is also accepted: it adds the rule's `weight` to the deprecated `score` response field and never changes the recommendation.
</ParamField>

<ParamField body="match" type="string" default="any">
  How the groups combine: `any` (one group must match) or `all` (every group must match).
</ParamField>

<ParamField body="on_unknown" type="string" default="review">
  What happens when the rule can't be evaluated: `review`, `skip` or `apply`. See [Unknown data](/api/risk-platform/policies#unknown-data).
</ParamField>

<ParamField body="groups" type="array" required>
  At least one group. Each group has a `match` (`all` by default, or `any`) and at least one condition.

  <Expandable title="condition properties">
    <ParamField body="field" type="string" required>
      A registry field, such as `email.is_disposable` or `ip.country_code`.
    </ParamField>
    <ParamField body="op" type="string" required>
      An operator the field accepts, such as `is_true`, `in` or `in_list`.
    </ParamField>
    <ParamField body="value" type="string | number | boolean | array">
      The value to compare. Leave it out for operators that take none, such as `is_true`. For `in` and `not_in`, send an array (`["IR", "KP"]`) or a comma-separated string (`"IR,KP"`); it's stored as a string. For `in_list` and `not_in_list`, send the list ID.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="weight" type="number">
  Used only by `add_to_score` rules.
</ParamField>

<ParamField body="side_effects" type="array">
  Lists to update when the rule matches. Each entry is `{ "type": "add_to_list", "list_id": "...", "field": "email.address" }`, and adds the check's value of `field` to the list. `field` must be `email.address`, `ip.address` or `phone.number`, matching the list's kind.
</ParamField>

Fields other than these are ignored and never stored.

## List all policies

```bash
curl '{{RISK_API_BASE_URL}}/v1/policies' \
  -H 'Authorization: Bearer mk_...'
```

Returns `{ "policies": [...] }`, oldest first. Archived policies are included, with `archived_at` set.

## Retrieve a policy

```bash
curl '{{RISK_API_BASE_URL}}/v1/policies/signup_protection' \
  -H 'Authorization: Bearer mk_...'
```

Returns the policy object, or `404` with reason `policy_not_found`.

## List versions

```bash
curl '{{RISK_API_BASE_URL}}/v1/policies/signup_protection/versions?limit=50' \
  -H 'Authorization: Bearer mk_...'
```

<ParamField query="limit" type="integer" default="50">
  How many versions to return, newest first, from 1 to 200.
</ParamField>

```json
{
  "policy_id": "signup_protection",
  "current_version": 9,
  "versions": [
    {
      "version": 9,
      "created_at": "2026-11-05T10:12:00Z",
      "created_by_email": "jane@example.com",
      "created_via": "management_key",
      "management_key_label": "Policy agent",
      "change": { "type": "replace_rule", "rule_id": "R2" },
      "rules": [ ... ],
      "diff": {
        "added": [],
        "removed": [],
        "changed": [ { "before": { ... }, "after": { ... } } ]
      }
    }
  ]
}
```

<ResponseField name="created_via" type="string | null">
  `dashboard` or `management_key`.
</ResponseField>

<ResponseField name="management_key_label" type="string | null">
  The name of the Management key that made the change, when one did.
</ResponseField>

<ResponseField name="change" type="object">
  What the version did: `type` is `add_rule`, `replace_rule` or `delete_rule` (with `rule_id`), `rollback` (with `to_version`), or `create` or `edit` for changes made in the dashboard.
</ResponseField>

<ResponseField name="diff" type="object | null">
  The rules `added`, `removed` and `changed` (with `before` and `after`) compared with the previous version. `null` for the oldest version.
</ResponseField>

## Add a rule

Adds one rule at the end of the policy. The server assigns its ID; an `id` in the body is ignored.

```bash
curl -X POST '{{RISK_API_BASE_URL}}/v1/policies/signup_protection/rules' \
  -H 'Authorization: Bearer mk_...' \
  -H 'Content-Type: application/json' \
  -d '{
    "expected_version": 8,
    "rule": {
      "label": "Disposable email",
      "action": "review",
      "groups": [{ "match": "all", "conditions": [
        { "field": "email.is_disposable", "op": "is_true" }
      ]}]
    }
  }'
```

<ParamField body="expected_version" type="integer" required>
  The policy version your change is based on.
</ParamField>

<ParamField body="rule" type="object" required>
  The new rule. See [The rule object](#the-rule-object).
</ParamField>

Returns `201` with the updated `policy` and `change`: `{ "type": "add_rule", "rule_id": "R6", "before": null, "after": { ... } }`.

## Replace a rule

Replaces one rule in place. Every other rule is kept as it is.

```bash
curl -X PUT '{{RISK_API_BASE_URL}}/v1/policies/signup_protection/rules/R2' \
  -H 'Authorization: Bearer mk_...' \
  -H 'Content-Type: application/json' \
  -d '{
    "expected_version": 8,
    "rule": {
      "label": "Blocked countries",
      "action": "block",
      "match": "any",
      "on_unknown": "review",
      "groups": [{ "match": "all", "conditions": [
        { "field": "ip.country_code", "op": "in", "value": ["IR", "KP"] }
      ]}]
    }
  }'
```

<ParamField body="expected_version" type="integer" required>
  The policy version your change is based on.
</ParamField>

<ParamField body="rule" type="object" required>
  The complete replacement rule. `rule.id` must be omitted or equal to the rule ID in the path; otherwise the response is `400` with reason `rule_id_mismatch`.
</ParamField>

Returns `200` with the updated `policy` and `change`: `type` `replace_rule`, `rule_id`, `unchanged` (`true` when the rule was already identical and no version was added), `before` and `after`.

## Delete a rule

```bash
curl -X DELETE '{{RISK_API_BASE_URL}}/v1/policies/signup_protection/rules/R5?expected_version=9' \
  -H 'Authorization: Bearer mk_...'
```

<ParamField query="expected_version" type="integer" required>
  The policy version your change is based on. You can send it in the JSON body instead.
</ParamField>

Returns `200` with the updated `policy` and `change`: `type` `delete_rule`, `rule_id`, `before` (the deleted rule) and `after: null`. The deleted rule's ID is never given to another rule.

## Roll back

Adds a new version with the rules of an earlier version. History is never rewound: the versions in between stay in the history.

```bash
curl -X POST '{{RISK_API_BASE_URL}}/v1/policies/signup_protection/rollback' \
  -H 'Authorization: Bearer mk_...' \
  -H 'Content-Type: application/json' \
  -d '{ "expected_version": 9, "to_version": 8 }'
```

<ParamField body="expected_version" type="integer" required>
  The policy's current version.
</ParamField>

<ParamField body="to_version" type="integer" required>
  The earlier version whose rules to restore.
</ParamField>

Returns `200` with the updated `policy` and `change`: `type` `rollback`, `to_version`, `unchanged` (`true` when `to_version` is the current version), and `diff`, the rules added, removed and changed by the rollback.

## List rule fields

Returns every field a rule can test, with the operators each one accepts, so you can write rules that pass validation.

```bash
curl '{{RISK_API_BASE_URL}}/v1/registry' \
  -H 'Authorization: Bearer mk_...'
```

```json
{
  "fields": [
    {
      "field": "email.is_disposable",
      "type": "bool",
      "description": "Domain is a known disposable provider",
      "operators": [
        { "op": "is_true", "label": "is true", "value_kind": "none" },
        { "op": "is_false", "label": "is false", "value_kind": "none" }
      ]
    }
  ],
  "value_sets": { "country": [ { "value": "US", "label": "United States" } ] },
  "rule_actions": ["allow", "block", "review", "add_to_score"],
  "on_unknown": ["review", "skip", "apply"]
}
```

<ResponseField name="fields" type="array">
  Each field with its `type` (`string`, `bool`, `number` or `enum`), a `description`, its allowed `options` for enum fields, and its `operators`. An operator's `value_kind` says what value it takes, for example `none`, `number`, `choice` or `list`.
</ResponseField>

<ResponseField name="value_sets" type="object">
  Suggested values for some fields, such as country codes.
</ResponseField>

## Errors

| Status | `reason` | Meaning |
|---|---|---|
| 400 | `malformed_json` | The body isn't a JSON object. |
| 400 | `expected_version_required` | Send `expected_version`. |
| 400 | `invalid_rule` | The resulting rules failed validation. See `issues`. |
| 400 | `rule_id_mismatch` | `rule.id` doesn't match the rule ID in the path. |
| 400 | `to_version_required` | A rollback needs `to_version`. |
| 401 | `unauthorized` | Missing, invalid, revoked or expired key. |
| 403 | `management_key_required` | These endpoints need a Management key. |
| 404 | `policy_not_found` | No policy with this ID. |
| 404 | `rule_not_found` | No rule with this ID in the policy. |
| 404 | `version_not_found` | The `to_version` doesn't exist for this policy. |
| 409 | `version_conflict` | The policy changed since `expected_version`. The response includes `current_version`. |
| 409 | `policy_archived` | Restore the policy in the dashboard before changing it. |

See [Errors](/api/risk-platform/api-reference/errors) for the error format.
